# Skilldeck — реестр

Данные каталога [skilldeck.ru](https://skilldeck.ru): отобранные скиллы для
Claude Code и Codex. Сайт собирается из этого репозитория. Код самих
скиллов здесь не лежит, только карточки со ссылкой на репозиторий автора
и закреплённым коммитом.

## Что внутри

- `skills/<имя>/entry.md` — карточка: фронтматтер по схеме
  `schema/entry.schema.json`, в теле — «Зачем он мне». Карточки с
  `draft: true` — кандидаты, на сайт не попадают.
- `tasks.yaml` — задачи, под которые ставят скиллы.
- `protocol.md` — как скиллы попадают в каталог и что проверяет разбор кода.
- `stats.json` — снимок звёзд GitHub с датой.
- `candidates.json` — кандидаты в каталог от сборщика (`discover.mjs`):
  что нашлось на GitHub и чего ещё нет в реестре. Это список для отбора,
  не карточки. В git его нет (14 МБ, пересобирается за один запуск);
  в репозитории — `candidates.md`, короткая сводка с топом для отбора пачкой.
- `scripts/` — проверка (`validate.mjs`), сборка `index.json`
  (`build-index.mjs`), приём скилла (`intake.mjs`), снимок звёзд
  (`github-stats.mjs`), сборщик кандидатов (`discover.mjs`); общий код
  запросов к GitHub и разбора SKILL.md — `github.mjs`.

## Проверка

```bash
npm ci
npm run validate               # всё, включая черновики
npm run validate -- --production  # то, что уходит на сайт
```

## Сборщик кандидатов

```bash
GITHUB_TOKEN=$(gh auth token) npm run discover
```

Пишет `candidates.json` и сводку `candidates.md`. Каталог растёт ручным
отбором пачками по 20–30 скиллов, автоприёма нет: сводка — топ-100 по
звёздам среди того, чего нет в реестре, не больше трёх скиллов из одного
репозитория, без архивных и без description. Колонки — имя со ссылкой,
репозиторий, описание, звёзды, дата последнего коммита, лицензия. Что уже
в реестре — строкой над таблицей. Пересобрать только сводку:
`npm run discover -- --md-only`.

Источники:

- репозитории карточек реестра — для сверки «уже есть / нет»;
- известные сборники (`CONFIG.collections` в `scripts/discover.mjs`:
  `anthropics/skills`, `obra/superpowers`, `openai/skills` и другие);
- awesome-списки (`CONFIG.awesomeLists`): все ссылки на репозитории из README;
- поиск репозиториев по темам GitHub (`agent-skills`, `claude-skills` и др.),
  срезами по звёздам;
- поиск кода `filename:SKILL.md` срезами по размеру файла. Это выборка, не
  перепись: SKILL.md на GitHub миллионы, поиск отдаёт до 1000 на запрос
  и 10 запросов в минуту.

Репозитории вне реестра и сборников берутся от `--min-stars` звёзд
(по умолчанию 20) и не форки. В каждом читается дерево на голове ветки
по умолчанию и фронтматтер всех SKILL.md. Копии одного скилла под разных
агентов (`.claude/skills`, `.codex/skills`, `plugins/…`) в одном репозитории
сливаются по имени в одну запись с `variants`; одинаковый SKILL.md (или
те же name и description) в разных репозиториях — в одну с `copies` (главная копия — из реестра, потом не из
сборника, потом с большим числом звёзд).

Поля записи — сначала те, по которым решают: `name`, `description`
(из фронтматтера; битый YAML разбирается регуляркой, как в `intake.mjs`,
и попадает в `spec_issues`), `stars` и `last_commit` — у репозитория,
не у скилла; `license` (файл LICENSE в папке скилла важнее лицензии
репозитория), `in_registry` — имя карточки или `null`. Потом где лежит:
`repo`, `path` (папка скилла, `.` — корень), `found_by` — источники.
SKILL.md в папках тестов и фикстур не считаются. Вверху файла — сводка прогона, в том числе карточки реестра,
которых сборщик не нашёл.

Ключи: `--min-stars N`, `--code-pages N` (бюджет страниц поиска кода,
по умолчанию 100 — около 10 минут), `--fresh` (без кэша), `--out файл`.
Кэш деревьев и разобранных SKILL.md — в `.cache/discover.json` (в git не
идёт), ключ — коммит, поэтому повторный прогон дешёвый. Полный прогон
с пустым кэшем идёт около часа и может ждать сброса лимита GitHub.
