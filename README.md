# Skilldeck — реестр

Данные каталога [skilldeck.ru](https://skilldeck.ru): отобранные скиллы для
Claude Code и Codex. Сайт собирается из этого репозитория. Код самих
скиллов здесь не лежит, только карточки со ссылкой на репозиторий автора
и закреплённым коммитом.

## Что внутри

- `skills/<имя>/entry.md` — карточка: фронтматтер по схеме
  `schema/entry.schema.json`, в теле — «Зачем он мне». Карточки с
  `draft: true` — кандидаты, на сайт не попадают.
- `tasks.yaml` — задачи, под которые ставят скиллы.
- `protocol.md` — как скиллы попадают в каталог и что проверяет разбор кода.
- `stats.json` — снимок звёзд GitHub с датой.
- `scripts/` — проверка (`validate.mjs`), сборка `index.json`
  (`build-index.mjs`), приём скилла (`intake.mjs`), снимок звёзд
  (`github-stats.mjs`).
- `skills/<имя>/evals.yaml` и `skills/<имя>/inputs/` — набор задач для
  прогона, схема `schema/evals.schema.json`.
- `runner/` — обвязка прогона (`run.mjs`) и детерминированные проверки
  (`checks/`).

## Проверка

```bash
npm ci
npm run validate               # всё, включая черновики
npm run validate -- --production  # то, что уходит на сайт
```

`validate` проверяет и наборы задач: схему, файлы входов, что есть обычный
и плохой вход, что проверки ссылаются на известные входы и существующие
скрипты, что в задании есть `{output}`.

## Прогон

Прогон делается по [`protocol.md`](protocol.md): те же задачи со скиллом и
без, слепой критик. Нужны карточка с `source.commit` и набор задач.

### Набор задач `skills/<имя>/evals.yaml`

```yaml
version: 1
prompt: |            # задание агенту, одно для обоих плеч; скилл не называть
  Приведи типографику текста в файле {input} … запиши в файл {output}.
inputs:              # две-три обычные задачи и хотя бы один плохой вход
  - { id: news-post, kind: typical, title: "…", file: inputs/news-post.md, source: "…" }
  - { id: english-notes, kind: bad, title: "…", file: inputs/english-notes.md, source: "…" }
checks:
  - id: typography   # детерминированная: считает скрипт
    kind: script
    title: "…"
    run: "python3 runner/checks/ru-typography.py violations {output}"
    better: lower    # какое value лучше при сравнении плеч
    inputs: [news-post]
  - id: typography-quality   # критерий для слепого критика
    kind: critic
    title: "…"
    criterion: "В каком выходе …?"
```

- **Входы только публикуемые**: они уходят на сайт вместе с прогоном. Свои
  тексты или открытые материалы; откуда вход — в `source`.
- **Плохой вход** — пустой, битый, чужой язык или задача не по профилю.
  Пустой файл допустим только у плохого входа.
- **Скрипт проверки** запускается из корня реестра, `{input}` и `{output}` —
  абсолютные пути. Печатает одну строку JSON `{"pass", "value", "detail"}`;
  ненулевой код выхода — сбой самой проверки, а не провал выхода. У скрипта
  должен быть `--selftest` на заведомо плохом и заведомо чистом тексте
  (пример — `runner/checks/ru-typography.py`).
- Нужен хотя бы один критерий для критика: без слепого сравнения прогона нет.

### Обвязка `runner/run.mjs`

```bash
node runner/run.mjs milchin --dry-run          # план и число вызовов claude -p
node runner/run.mjs milchin --demo             # пробный прогон, demo: true
node runner/run.mjs milchin rozental           # настоящий, пачкой
node runner/run.mjs milchin --resume 2026-11-21  # дописать прерванный
```

Скиллы — только явным списком: прогоны делят недельный лимит подписки.
На каждый скилл: `2 × входов` плеч и по два прохода критика на вход с
критериями. Флаги — в шапке `run.mjs`: `--model` (плечи, по умолчанию
`sonnet`), `--critic-model` (`opus`), `--parallel` (3), `--timeout-min`,
`--budget`, `--keep-sandbox`, `--out`.

Что делает по шагам протокола:

1. **Установка.** Песочница во временной папке; ручная команда из карточки
   (`installCommands`, ставит закреплённый `source.commit`) с `HOME`
   песочницы, клон вместо `/tmp/<имя>` — в песочнице. Нет `SKILL.md` или
   HEAD клона не совпал с `source.commit` — прогон останавливается.
2. **Входы** — из `evals.yaml`, копия в рабочую папку плеча.
3. **Два плеча** `claude -p` на каждый вход, у каждого своя чистая копия:
   со скиллом — `HOME`, где лежит только он; без скилла — пустой `HOME`.
   Флаги одинаковые: `--tools Bash,Read,Write,Edit,Glob,Grep,Skill`,
   `--setting-sources user`, `--strict-mcp-config`, `--no-session-persistence`,
   `--max-budget-usd`. `--setting-sources ""` не годится: при нём
   пользовательские скиллы не грузятся, и плечо «со скиллом» молча
   становится вторым плечом без него. Окружение собирается с нуля (никаких
   токенов и переменных родительской сессии), `CLAUDE_CODE_TMPDIR` — в
   песочнице. Процесс завёрнут в `sandbox-exec`: запись только в папку
   плеча, домашняя папка не читается, кроме установки `claude`. Сеть не
   ограничена.
4. **Слепой критик** — голый вызов (`--tools ""`, `--setting-sources ""`):
   задание, вход и два выхода «A» и «B» без пометок, по критериям из
   `evals.yaml`. Два прохода: порядок первого случайный, во втором
   переставлен. Совпали — их выбор, разошлись — ничья. Невидимые символы
   (неразрывный пробел, нулевой ширины, BOM) и латинские буквы внутри
   русских слов критику показываются знаками, одинаково во входе и обоих
   выходах: без этого он выносит ничью там, где выходы различаются только
   невидимым. Фразы критика о каждом выходе идут в `with_skill` и `baseline`
   `run.yaml`.
5. **Что скилл делает с машиной** — что видно из прогона: запускал ли агент
   скрипты из папки скилла, какие файлы вне рабочей папки появились только
   в плече со скиллом (служебные файлы `claude` есть в обоих плечах и
   отсекаются сравнением). Сеть берётся из разбора кода. Код скилла читает
   человек.
6. **Вердикт** обвязка только предлагает, по правилу из `notes.md`;
   подтверждает или правит его человек.

Куда пишет: настоящий прогон — `skills/<имя>/runs/<дата>/` (`run.yaml`,
`with-skill/`, `baseline/`, `evidence.json` с проверками и ответами критика,
`notes.md`), демо — `../drafts/eval-runs/<имя>/<дата>/`, чтобы
`validate --production` и деплой не упали на `demo: true`. Сырые логи
(stream-json плеч, промпты критика) — в `../drafts/eval-runs/<имя>/<дата>/raw/`,
в git не идут. Записанный `run.yaml` обвязка сразу проверяет тем же кодом,
что и `validate`.

Авторизация: в чистом `HOME` логин CLI не виден, нужен токен
`claude setup-token` в Keychain (служба `claude-code-oauth-token`) или
`ANTHROPIC_API_KEY`. Упёрлись в недельный лимит — обвязка останавливает
очередь и подсказывает `--resume`; готовые плечи не перезапускаются,
установка и критик проходят заново.

`cost.tokens` — все токены вызовов вместе с кэшем (долю чтения кэша
пишет `notes.md`), `cost.minutes` — сумма длительностей вызовов `claude`:
от `--parallel` и `--resume` не зависит.

Работает только на macOS (`sandbox-exec`, Keychain).
